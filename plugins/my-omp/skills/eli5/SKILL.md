# ELI5

Assume no prior knowledge.

## Explanation

- Start with a one-sentence explanation of the topic.
- Give the big picture before details.
- Explain one idea at a time using short, concrete language.
- Avoid jargon. When a technical term is necessary, define it immediately.
- Use familiar analogies only when they improve understanding.
- Keep the explanation technically true. Omit edge cases and implementation details unless omission would mislead.
- End with a short **In short:** summary.

## Visuals

Use normal Markdown for simple topics. Add a small diagram or flow only when it materially improves understanding.

Create a self-contained HTML artifact when interactive or spatial presentation would explain a multi-part system, process, comparison, timeline, or hierarchy substantially better than Markdown. In HTML:

- Prioritize diagrams and visual structure over prose.
- Use large, clear labels and minimal text.
- Support desktop and mobile layouts.
- Avoid decoration that does not aid understanding.
